# AGENTS.md

Repo-specific notes for working on **FiveSync UI** (Roblox UI library, based on Arcane/Compkiller).

## Layout

- `inject.lua` — the library itself (single file, ~10.7k lines). Loaded by users via `loadstring(game:HttpGet(...))()`.
- `example.lua` — the original kitchen-sink example (every element, configs, themes).
- `template.lua` — clean, documented starter for building a panel. Preferred reference for the public API.
- `Script/` — user-provided scripts (not part of the library).

## Branding

The library is **FiveSync UI by EntreViela$ Team**. Logo asset: `rbxassetid://117056629401480`.
Palette is black + neon white. Do not reintroduce the old names (`Compkiller`, `Arcane`) — see git history / PRs #4-#6.

## Toolchain

Luau is not in the repo. Get the binaries once:

```bash
curl -sL -o /tmp/luau.zip https://github.com/luau-lang/luau/releases/latest/download/luau-ubuntu.zip
mkdir -p /tmp/luaubin && python3 -c "import zipfile;zipfile.ZipFile('/tmp/luau.zip').extractall('/tmp/luaubin')"
chmod +x /tmp/luaubin/*
```

`/tmp` is wiped between sessions, so reinstall when `luau-compile` is missing.

## Verify before committing

```bash
/tmp/luaubin/luau-compile --binary inject.lua >/dev/null && echo OK
/tmp/luaubin/luau-compile --binary template.lua >/dev/null && echo OK
```

## Gotchas

- **`luau-compile` only catches syntax errors, not runtime errors.** A file can compile clean and still break at runtime. Always sanity-check API usage against the source.
- **Variable shadowing.** `inject.lua` used to declare `local FiveSync = Instance.new("ScreenGui")` inside `FiveSync.new` and `FiveSync:Loader`, which shadowed the library table and caused `_RandomString is not a valid member of ScreenGui`. The library is the table `local FiveSync = { ... }` (near the top); any GUI instance is named `ScreenGuiObj`. Never name a local `FiveSync`.
- **`AddToggle` returns an API table** (`SetValue` / `GetValue` / `SetText` / `GetText`), plus `Args.Link` for `AddKeybind` / `AddHelper` / `AddOption`. There is no `:Toggle()` method on the returned object.
- **`SetTheme` overwrites the whole palette**, so a config load can revert custom colors. `FiveSync.Colors` is the single source of truth.
- **Elements are only saved to config when they have a `Flag`.** Elements without a `Flag` are runtime-only.
- **Luau caps locals at 200 per function/chunk.** A long top-level script can exceed this and fail with `Out of local registers when trying to allocate X: exceeded limit 200` (the executor compiles with optimization off, so it *does* enforce the limit even when a local `luau-compile` passes). Fix by wrapping self-contained groups of statements in `do ... end` blocks so their locals are released at the block end. Reproduce locally with `luau-compile --binary -O0 Script/A`.
- **The executor truncates pasted text at ~64000 characters.** Pasting a big script inline fails with an EOF parse error mid-table (`Expected '}' ... got <eof>`). Load it by URL instead: `loadstring(game:HttpGet(".../Script/A"))()`.
- **Always-on loops cost FPS even when their feature is off.** `Script/A` used to `Connect` every feature's `RenderStepped`/`Heartbeat` loop at load and bail out inside the callback. Connect the loop only when the feature's toggle turns on and `Disconnect` when it turns off (see `Aimbot_SetActive`, `SA_SetActive`, `ESP_SetEnabled`, `MB_SetState`). The toggle `Callback` runs once at load with the `Default`, so wiring it to a setter keeps initial state correct.
- **Always-on metamethod hooks get flagged as "IndexInstance".** `hookmetamethod(game, "__index", ...)` / `"__namecall"` installed at load is what anti-cheat "IndexInstance" detectors look for. Install the Silent Aim hooks only when the feature is active and the selected method needs them, and restore the original when off (see `SA_UpdateHooks`, called from the Silent Aim toggle and the method dropdown). With Silent Aim off, no `__index`/`__namecall` hook exists.
- **A config load must not install runtime hooks mid-flight.** `LoadConfig`/`LoadConfigFromString` write every flag one at a time, so a feature that reacts to each `SetValue` re-installs (and removes) its hooks for intermediate states — exactly the churn an "IndexInstance" detector sees, which is why loading a saved config got the user kicked. `ConfigManager:ApplyConfig` (shared by both entry points) raises `FiveSync.__ConfigLoading` for the duration and then runs every `FiveSync:AddOnConfigLoad(fn)` listener once with the final values. Features that install runtime state must early-return from their update function while `FiveSync.__ConfigLoading` is true and register a post-load listener to re-sync (see `SA_UpdateHooks` + the `AddOnConfigLoad` call at the end of the Silent Aim block). Do not add a second code path that applies flags without going through `ApplyConfig`.
- **The menu key persists on its own, not only inside a saved config.** `Script/A` only auto-loads a config literally named `default`, so a user-chosen menu key was lost on the next execute. `FiveSync:SetMenuKeyPersist(path)` opts the window into `E$34x/Window.json`: `FiveSync.new` reads it while building the window and `WindowArgs:SetMenuKey` writes it on every change. Keep this separate from the config system so the key survives a plain re-execute.
- **Silent Aim keeps its target fresh on `RenderStepped`.** `SA_TargetLoop` recomputes the closest in-FOV target every frame (and rolls `Hit Chance` once per frame into `SA_ChanceOK`); the hook itself only redirects. Do not move target acquisition back to a `task.wait` loop: a stale target position is the main cause of missed shots. `SA_ValidateArgs` gates each redirect on the real argument types so unrelated `Raycast`/`FindPartOnRay` calls are never corrupted. The method dropdown is multi-select (`Multi = true`); while the user is picking, FiveSync passes a `{[value]=boolean}` map, but its `Default` (and a config restore) arrives as the array form `{"Raycast"}`, so the callback must accept both — otherwise loading a config cleared every method and the aim hooked nothing.
- **FOV Line is independent of the ESP toggle.** The FOV Line (center → Silent Aim/Aimbot target) has its own `Config.FOVLine.Enabled` and shares the ESP render loop: `ESP_UpdateLoop` connects while `Config.Enabled or Config.FOVLine.Enabled`. Keep the render gate and the loop controller in sync when touching either feature, otherwise turning ESP off silently kills the FOV Line (or leaves the loop running with nothing to draw). `FOVLine_SetEnabled` and `ESP_SetEnabled` both call `ESP_UpdateLoop`.
- **Slider <-> textbox pairs must guard against recursion.** `AddSlider`/`AddTextBox` `SetValue` fires the element `Callback`, so a pair where each callback calls the other's `SetValue` recurses infinitely and *stack-overflows on config load* (`GetConfig` reads every flag, `LoadConfig` writes them back). Keep a per-pair boolean guard (see `SpeedSyncing`, `FlySyncing`, `updating` in the Jump pair) and bail out at the top of each callback when it is set. The stack overflow only shows up at runtime, not in `luau-compile`.
- **A dropdown needs a `Default` to serialize.** A dropdown created without `Default` returns `nil` from `GetValue`; `GetConfig` then stores a `nil` value and the flag breaks config round-trip. Always give dropdowns an explicit `Default` (the whitelist player-picker does).
- **`GetConfig` only saves flagged elements.** `ConfigManager:WriteConfig` iterates `FiveSync.Flags`, so any element without a `Flag` is runtime-only and silently lost on save/load. Every user-facing control should carry a unique `Flag` (renaming a `Flag` invalidates saved configs that reference the old name).
- **On-screen HUD buttons mirror a menu `Flag`.** `Script/A`'s "Botões" tab (`QuickButtons`, persisted to `E$34x/QuickButtons.json`) draws draggable toggles that read/write another element's `Flag` via `FiveSync.Flags[name]:GetValue()/SetValue()`. A `RenderStepped`/`task.wait` poll keeps the button color in sync when the feature is toggled elsewhere. Drag and click are handled on the top `TextButton` (`entry.Click`, the only child that receives input): a short release toggles the flag, while holding `>= 3s` or moving the pointer more than 6px arms the drag. `StopDrag` saves the layout and runs from both the button's `InputEnded` and a `UserInputService.InputEnded` safety net, so a release off the button never leaves a stuck drag.
- **UI sounds are centralized in `FiveSync.Sounds`.** `FiveSync:_PlaySound(Key)` plays a cached `Sound` (one instance per key, parented to `CoreGui`, reused via `Sounds.__Cache`; gated by `Sounds.Enabled`). Keys: `TabChange` (top tab strip), `TabChange2` (inner tab strip), `ToggleOn`/`ToggleOff` (every toggle, including the HUD buttons), `Notify` (every `newNotify():new`), `MenuOpen` (window toggle), `Config` (config save/load). Sound ids live in `FiveSync.Sounds`, not in `Script/A`. `_MuteSounds(fn)` raises `Sounds.__Suppress` so a bulk `SetValue` (config load) plays nothing.
- **`FiveSync:Debounce(Delay, fn)` coalesces rapid calls.** It returns a wrapper that only runs `fn` with the *last* arguments after `Delay` seconds of quiet (the last call wins). Use it for any notification driven by a slider, otherwise dragging a 0–20 slider fires ~20 notifications. `Script/A` wraps the Speed/Spin/Fly/Sky/Camera-zoom notifiers this way.
- **Never call a `local function` before its declaration.** Luau resolves the name to a global (`nil`) at the call site, giving `attempt to call a nil value` at runtime, not at compile time. `RefreshVisual` (ESP HUD buttons) originally called `RefreshVisualAction`, declared just *after* it — reorder so the callee is defined first.
- **`AddKeybind`'s `Callback` only fires on rebind, not at load.** `Script/A`'s "Whitelist Key" wired a global (`Whitelist_Key`) through the keybind `Callback`, then read that global once at load to install the `UserInputService.InputBegan` listener. The `Callback` had not run yet, so the global was `nil`, the listener returned early and was never connected, and pressing the key did nothing forever. Seed the global with its `Default` *before* installing the listener and read it inside the handler, so the very first press works and later rebinds are picked up live. The "Whitelist Key" adds the player under the crosshair (Silent Aim target, else Aimbot target, else mouse/center-camera raycast) to the Aimbot whitelist; the same action is the `AddWL` HUD button and the "Add Alvo da Mira" button.
- **Box ESP fill must work in every mode.** `DrawESPBox` handles three modes: `Full` and `Corner` draw screen-space lines (a `Square` fill via `DrawRectFill`, with optional gradient), and `3D` projects the character's real bounding box — its fill is 6 `Quad` faces (`Draw3DFill`) that rotate with the camera. Older code disabled `BoxFill`/gradient for `Corner` and `3D`, so fill only worked in `Full`. `data.Box3DFill` must be initialized in `InitPlayerESP` and hidden/removed in the render gate, `ESP_HideAll`, and `ClearESP`.
- **Arrow/Circle ESP are extra per-player drawings.** `data.Arrow` (filled `Triangle` above the head) lives alongside the box. The Circle ESP is a **3D horizontal ring**: `DrawCircle3D` projects `CIRCLE_SEGMENTS` world points on the XZ plane at foot height (`char:GetBoundingBox()`, `radius = max(size.X, size.Z)/2`) through `Camera:WorldToViewportPoint`, then joins them with `data.Circle3D` `Line`s so the ring follows the camera and the character stays inside it (unlike the old screen-space `Circle`). With `Config.Circle.Filled` it also fills the disk with a fan of `data.Circle3DFill` `Triangle`s. Add `data.Circle3D`/`data.Circle3DFill` to `ClearESP`, `ESP_HideAll`, the render gate (off branch) and the off-screen hide branch; gate on `Config.Circle.Enabled`.
- **Text/health drawings must be hidden *and* removed, or they leak.** `ESP_HideAll` (ESP off) hid the text labels but left their `TextBackgrounds` squares visible; route the text through `HideText(t)` (which hides the shadow and background too). `ClearESP` (player left / died / char gone) removed the health bar and outline but not `data.HealthBarBackground`, leaving a black square. Every per-player drawing must be handled in both `ClearESP` and `ESP_HideAll`, or disabling ESP / a player leaving leaves stale pixels on screen.
- **The mock needs `Backpack` on each player.** The ESP `Item` render calls `player.Backpack:FindFirstChildOfClass("Tool")`; the mock player had no `Backpack`, so that line errored inside the render `pcall` and silently aborted the rest of the frame (Distance never drew). Real `Player` instances always have a `Backpack`; add one to the mock too.

- **Every toggle carries a visible keybind chip.** `AddToggle` (via the shared `AddToggleElement` helper) appends a `Keybind` link whose `_Input` calls `AutoKeybind.Open()`, so the bind menu is reachable by a plain left click instead of the hidden right-click. `AutoKeybind.__Sync` (a no-op hook `_KeybindHandler` exposes and calls on key/mode/config changes) mirrors the bound key into the chip and stores it as `AutoKeybind.__ChipText`. `AutoKeybind.Open`/`Close` fire the same `KB_Signal` the right-click path uses.
- **`AddToggle` is a thin wrapper over `local function AddToggleElement(...)`.** The full toggle construction lives in `AddToggleElement` so other call sites can reuse it; the `Args:AddToggle` method just forwards `Config`/`Parent`/`Signal`/`Zindex`/`EnabledLine`/`DisableStackKeybind` and returns the API table. Toggles also expose `Args.Root` (the row frame) for tests and callers.

- **Local runtime harness.** `/tmp/mock/` is a fake Roblox env for running `Script/A` end to end: `roblox_mock.lua` (services, players, Drawing, vector math, `RunService` connection capture, `hookmetamethod`/`getnamecallmethod` stubs, in-memory filesystem + JSON), and `harness.py` which inlines mock + `inject.lua` + `Script/A` + an optional driver into one sandbox and builds `setup.lua`. Run `python3 /tmp/mock/harness.py <driver>.lua` then `/tmp/luaubin/luau setup.lua`. Top-level chunks are run in coroutines and driven, because `task.wait` yields. Test drivers must read harness state through globals (`__FIVESYNC`, `__M`, `readfile`), not `__ENV`, because the driver chunk is a separate sandbox. Drivers: `smoke.lua`, `config_test.lua`, `config_roundtrip.lua`, `save_all.lua`, `button_test.lua`, `silentaim_test.lua`, `esp_cleanup_test.lua` (no stale drawings after ESP off / player death / player leave), `esp_circle3d_test.lua` (Circle ESP is a horizontal world-space ring with the character inside), plus `kb*_test.lua` (keybind menu/chip), `sound_test.lua`, `drag_test.lua`. The mock implements `Sound` (with a `G.__sounds` play log), `Vector2`, and `UserInputState` for these. `/tmp` is wiped between sessions, so rebuild the harness when it is gone.
