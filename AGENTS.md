# AGENTS.md

Repo-specific notes for working on **FiveSync UI** (Roblox UI library, based on Arcane/Compkiller).

## Layout

- `inject.lua` — the library itself (single file, ~10.7k lines). Loaded by users via `loadstring(game:HttpGet(...))()`.
- `example.lua` — the original kitchen-sink example (every element, configs, themes).
- `template.lua` — clean, documented starter for building a panel. Preferred reference for the public API.
- `Script/` — user-provided scripts (not part of the library).

## Branding

The library is **FiveSync UI by EntreViela$ Team**. Logo asset: `rbxassetid://117056629401480`.
Palette is black + neon white. Do not reintroduce the old names (`Compkiller`, `Arcane`) — see git history / PRs #4-#6.

## Toolchain

Luau is not in the repo. Get the binaries once:

```bash
curl -sL -o /tmp/luau.zip https://github.com/luau-lang/luau/releases/latest/download/luau-ubuntu.zip
mkdir -p /tmp/luaubin && python3 -c "import zipfile;zipfile.ZipFile('/tmp/luau.zip').extractall('/tmp/luaubin')"
chmod +x /tmp/luaubin/*
```

`/tmp` is wiped between sessions, so reinstall when `luau-compile` is missing.

## Verify before committing

```bash
/tmp/luaubin/luau-compile --binary inject.lua >/dev/null && echo OK
/tmp/luaubin/luau-compile --binary template.lua >/dev/null && echo OK
```

## Gotchas

- **`luau-compile` only catches syntax errors, not runtime errors.** A file can compile clean and still break at runtime. Always sanity-check API usage against the source.
- **Variable shadowing.** `inject.lua` used to declare `local FiveSync = Instance.new("ScreenGui")` inside `FiveSync.new` and `FiveSync:Loader`, which shadowed the library table and caused `_RandomString is not a valid member of ScreenGui`. The library is the table `local FiveSync = { ... }` (near the top); any GUI instance is named `ScreenGuiObj`. Never name a local `FiveSync`.
- **`AddToggle` returns an API table** (`SetValue` / `GetValue` / `SetText` / `GetText`), plus `Args.Link` for `AddKeybind` / `AddHelper` / `AddOption`. There is no `:Toggle()` method on the returned object.
- **`SetTheme` overwrites the whole palette**, so a config load can revert custom colors. `FiveSync.Colors` is the single source of truth.
- **Elements are only saved to config when they have a `Flag`.** Elements without a `Flag` are runtime-only.
- **Luau caps locals at 200 per function/chunk.** A long top-level script can exceed this and fail with `Out of local registers when trying to allocate X: exceeded limit 200` (the executor compiles with optimization off, so it *does* enforce the limit even when a local `luau-compile` passes). Fix by wrapping self-contained groups of statements in `do ... end` blocks so their locals are released at the block end. Reproduce locally with `luau-compile --binary -O0 Script/A`.
- **The executor truncates pasted text at ~64000 characters.** Pasting a big script inline fails with an EOF parse error mid-table (`Expected '}' ... got <eof>`). Load it by URL instead: `loadstring(game:HttpGet(".../Script/A"))()`.
- **Always-on loops cost FPS even when their feature is off.** `Script/A` used to `Connect` every feature's `RenderStepped`/`Heartbeat` loop at load and bail out inside the callback. Connect the loop only when the feature's toggle turns on and `Disconnect` when it turns off (see `Aimbot_SetActive`, `SA_SetActive`, `ESP_SetEnabled`, `MB_SetState`). The toggle `Callback` runs once at load with the `Default`, so wiring it to a setter keeps initial state correct.
- **Always-on metamethod hooks get flagged as "IndexInstance".** `hookmetamethod(game, "__index", ...)` / `"__namecall"` installed at load is what anti-cheat "IndexInstance" detectors look for. Install the Silent Aim hooks only when the feature is active and the selected method needs them, and restore the original when off (see `SA_UpdateHooks`, called from the Silent Aim toggle and the method dropdown). With Silent Aim off, no `__index`/`__namecall` hook exists.
- **A config load must not install runtime hooks mid-flight.** `LoadConfig`/`LoadConfigFromString` write every flag one at a time, so a feature that reacts to each `SetValue` re-installs (and removes) its hooks for intermediate states — exactly the churn an "IndexInstance" detector sees, which is why loading a saved config got the user kicked. `ConfigManager:ApplyConfig` (shared by both entry points) raises `FiveSync.__ConfigLoading` for the duration and then runs every `FiveSync:AddOnConfigLoad(fn)` listener once with the final values. Features that install runtime state must early-return from their update function while `FiveSync.__ConfigLoading` is true and register a post-load listener to re-sync (see `SA_UpdateHooks` + the `AddOnConfigLoad` call at the end of the Silent Aim block). Do not add a second code path that applies flags without going through `ApplyConfig`.
- **The menu key persists on its own, not only inside a saved config.** `Script/A` only auto-loads a config literally named `default`, so a user-chosen menu key was lost on the next execute. `FiveSync:SetMenuKeyPersist(path)` opts the window into `E$34x/Window.json`: `FiveSync.new` reads it while building the window and `WindowArgs:SetMenuKey` writes it on every change. Keep this separate from the config system so the key survives a plain re-execute.
- **Silent Aim keeps its target fresh on `RenderStepped`.** `SA_TargetLoop` recomputes the closest in-FOV target every frame (and rolls `Hit Chance` once per frame into `SA_ChanceOK`); the hook itself only redirects. Do not move target acquisition back to a `task.wait` loop: a stale target position is the main cause of missed shots. `SA_ValidateArgs` gates each redirect on the real argument types so unrelated `Raycast`/`FindPartOnRay` calls are never corrupted. The method dropdown is multi-select (`Multi = true`); while the user is picking, FiveSync passes a `{[value]=boolean}` map, but its `Default` (and a config restore) arrives as the array form `{"Raycast"}`, so the callback must accept both — otherwise loading a config cleared every method and the aim hooked nothing.
- **FOV Line is independent of the ESP toggle.** The FOV Line (center → Silent Aim/Aimbot target) has its own `Config.FOVLine.Enabled` and shares the ESP render loop: `ESP_UpdateLoop` connects while `Config.Enabled or Config.FOVLine.Enabled`. Keep the render gate and the loop controller in sync when touching either feature, otherwise turning ESP off silently kills the FOV Line (or leaves the loop running with nothing to draw). `FOVLine_SetEnabled` and `ESP_SetEnabled` both call `ESP_UpdateLoop`.
- **The FOV Line must re-validate its target every frame, not trust the stored part.** `FOVLineTargetValid` is the gate before drawing; it now starts with `part:IsDescendantOf(game)`. Checking only `part.Parent` was not enough: when a player leaves or dies, the character Model is detached from the world (its `Parent` becomes `nil`, but the stored part reference stays valid), so the line stayed pinned at the last position. `IsDescendantOf(game)` rejects anything that left the world at any depth. Keep the team/whitelist/health checks too — the line must mirror the aim's rules.
- **One FOV center helper feeds both the drawing and the aim.** `FiveSync:GetFOVCenter("Screen"|"Mouse")` returns the viewport center or the cursor (adding the `GuiService:GetGuiInset().Y`, because `GetMouseLocation` is relative to the top of the screen while `WorldToViewportPoint` includes the inset). The Aimbot (`GetClosestPlayer`, `Aimbot_Render` — including the `Traçado` line offsets) and Silent Aim (`SA_UpdateTarget`, `SA_FOVRender`) all call it with `getgenv().Aimbot_FOVFollowMouse`/`SilentAim_FOVFollowMouse`. Always pass the same center to the visual and the acquisition, or the circle and the selection disagree. `UpdateTracedLines` repositions the `Traçado` drawings each frame so they follow a moving center.
- **Slider <-> textbox pairs must guard against recursion.** `AddSlider`/`AddTextBox` `SetValue` fires the element `Callback` when the value actually changes, so a pair where each callback calls the other's `SetValue` recurses infinitely and *stack-overflows on config load* (`GetConfig` reads every flag, `LoadConfig` writes them back). Keep a per-pair boolean guard (see `SpeedSyncing`, `FlySyncing`, `updating` in the Jump pair) and bail out at the top of each callback when it is set. The stack overflow only shows up at runtime, not in `luau-compile`.
- **`SetValue` is a no-op when the value already matches.** Every element's `SetValue` compares against its current value with `FiveSync:__SameValue` (or `__SameTable` for dropdowns) and skips the `Callback` when nothing changed. Config restore writes all flags straight from disk, so without this a feature whose saved value already matched still re-ran its callback — re-installing hooks and rewriting properties it never owned. `__SameValue` compares `Color3` with a tolerance because the picker stores HSV and the RGB round-trip is off by float error. Programmatic `SetValue` must never look like a user edit; when adding a new element type, route its setter through the same guard.
- **The colour picker panel fires its own `Callback`.** `_AddColorPickerPanel`'s `Args:Update(Silent)` calls the `Callback` so dragging updates the feature live. Every programmatic refresh (`SetValue`, and the construction-time `Update`) passes `Silent = true`, otherwise one `SetValue` fires the `Callback` twice and the construction pass overwrites `Config.Default` with the HSV round-trip of the colour.
- **Turning a feature off must restore what it changed, not stamp defaults.** Noclip snapshots each part's `CanCollide` into `NoclipSaved` (weak-keyed, so the dead character's parts drop out) and restores it in `NoclipRestore`; forcing `true` everywhere broke R6 characters (limbs are `CanCollide = false`, so the character tripped and could not climb ladders). `NoclipParts` is cached and refreshed by `ChildAdded`/`ChildRemoved` instead of walking `GetDescendants()` on every physics step — but the step callback also compares `GetChar()` against `NoclipChar`, because `Script/A`'s `CharacterAdded` handler waits 0.3 s before restarting noclip and the new body would be solid during that window. The hitbox snapshots `Size`/`Transparency`/`BrickColor`/`Material`/`CanCollide`/`Massless` per part in the weak-keyed `HitboxSnapshots` table and restores that, and `HitboxExpand` only writes a property when the value differs (the size sliders re-apply to every player on each drag). Polling every 0.5 s to reapply was replaced by `PlayerAdded` / `CharacterAdded` connections (`HitboxStartWatching`); that watcher keeps one connection per player in `hitboxPlayerConns` and drops it on `PlayerRemoving`, otherwise the table grows for the whole session.
- **A dropdown needs a `Default` to serialize.** A dropdown created without `Default` returns `nil` from `GetValue`; `GetConfig` then stores a `nil` value and the flag breaks config round-trip. Always give dropdowns an explicit `Default` (the whitelist player-picker does).
- **`GetConfig` only saves flagged elements.** `ConfigManager:WriteConfig` iterates `FiveSync.Flags`, so any element without a `Flag` is runtime-only and silently lost on save/load. Every user-facing control should carry a unique `Flag` (renaming a `Flag` invalidates saved configs that reference the old name).
- **On-screen HUD buttons mirror a menu `Flag`.** `Script/A`'s "Botões" tab (`QuickButtons`, persisted to `E$34x/QuickButtons.json`) draws draggable toggles that read/write another element's `Flag` via `FiveSync.Flags[name]:GetValue()/SetValue()`. A `RenderStepped`/`task.wait` poll keeps the button color in sync when the feature is toggled elsewhere. Drag and click are handled on the top `TextButton` (`entry.Click`, the only child that receives input): a short release toggles the flag, while holding `>= 3s` or moving the pointer more than 6px arms the drag. `StopDrag` saves the layout and runs from both the button's `InputEnded` and a `UserInputService.InputEnded` safety net, so a release off the button never leaves a stuck drag.
- **UI sounds are centralized in `FiveSync.Sounds`.** `FiveSync:_PlaySound(Key)` plays a cached `Sound` (one instance per key, parented to `CoreGui`, reused via `Sounds.__Cache`; gated by `Sounds.Enabled`). Keys: `TabChange` (top tab strip), `TabChange2` (inner tab strip), `ToggleOn`/`ToggleOff` (every toggle, including the HUD buttons), `Notify` (every `newNotify():new`), `MenuOpen` (window toggle), `Config` (config save/load). Sound ids live in `FiveSync.Sounds`, not in `Script/A`. `_MuteSounds(fn)` raises `Sounds.__Suppress` so a bulk `SetValue` (config load) plays nothing.
- **`FiveSync:Debounce(Delay, fn)` coalesces rapid calls.** It returns a wrapper that only runs `fn` with the *last* arguments after `Delay` seconds of quiet (the last call wins). Use it for any notification driven by a slider, otherwise dragging a 0–20 slider fires ~20 notifications. `Script/A` wraps the Speed/Spin/Fly/Sky/Camera-zoom notifiers this way.
- **Never call a `local function` before its declaration.** Luau resolves the name to a global (`nil`) at the call site, giving `attempt to call a nil value` at runtime, not at compile time. `RefreshVisual` (ESP HUD buttons) originally called `RefreshVisualAction`, declared just *after* it — reorder so the callee is defined first.
- **`AddKeybind`'s `Callback` only fires on rebind, not at load.** `Script/A`'s "Whitelist Key" wired a global (`Whitelist_Key`) through the keybind `Callback`, then read that global once at load to install the `UserInputService.InputBegan` listener. The `Callback` had not run yet, so the global was `nil`, the listener returned early and was never connected, and pressing the key did nothing forever. Seed the global with its `Default` *before* installing the listener and read it inside the handler, so the very first press works and later rebinds are picked up live. The "Whitelist Key" adds the player under the crosshair (Silent Aim target, else Aimbot target, else mouse/center-camera raycast) to the Aimbot whitelist; the same action is the `AddWL` HUD button and the "Add Alvo da Mira" button.
- **Box ESP fill must work in every mode.** `DrawESPBox` handles three modes: `Full` and `Corner` draw screen-space lines (a `Square` fill via `DrawRectFill`, with optional gradient), and `3D` projects the character's real bounding box — its fill is 6 `Quad` faces (`Draw3DFill`) that rotate with the camera. Older code disabled `BoxFill`/gradient for `Corner` and `3D`, so fill only worked in `Full`. `data.Box3DFill` must be initialized in `InitPlayerESP` and hidden/removed in the render gate, `ESP_HideAll`, and `ClearESP`.
- **Arrow/Circle ESP are extra per-player drawings.** `data.Arrow` (filled `Triangle` above the head) lives alongside the box. The Circle ESP is a **3D horizontal ring**: `DrawCircle3D` projects `CIRCLE_SEGMENTS` world points on the XZ plane at foot height (`char:GetBoundingBox()`, `radius = max(size.X, size.Z)/2`) through `Camera:WorldToViewportPoint`, then joins them with `data.Circle3D` `Line`s so the ring follows the camera and the character stays inside it (unlike the old screen-space `Circle`). With `Config.Circle.Filled` it also fills the disk with a fan of `data.Circle3DFill` `Triangle`s. Add `data.Circle3D`/`data.Circle3DFill` to `ClearESP`, `ESP_HideAll`, the render gate (off branch) and the off-screen hide branch; gate on `Config.Circle.Enabled`.
- **Text/health drawings must be hidden *and* removed, or they leak.** `ESP_HideAll` (ESP off) hid the text labels but left their `TextBackgrounds` squares visible; route the text through `HideText(t)` (which hides the shadow and background too). `ClearESP` (player left / died / char gone) removed the health bar and outline but not `data.HealthBarBackground`, leaving a black square. Every per-player drawing must be handled in both `ClearESP` and `ESP_HideAll`, or disabling ESP / a player leaving leaves stale pixels on screen.
- **The mock needs `Backpack` on each player.** The ESP `Item` render calls `player.Backpack:FindFirstChildOfClass("Tool")`; the mock player had no `Backpack`, so that line errored inside the render `pcall` and silently aborted the rest of the frame (Distance never drew). Real `Player` instances always have a `Backpack`; add one to the mock too.
- **The mock must mirror the real DataModel shape.** Parent every service under `game` (as Roblox does) so `part:IsDescendantOf(game)` answers correctly; expose direct child access (`char.HumanoidRootPart`, `char.Head`) in `instanceIndex`; and give `Humanoid` a `HipHeight`, `BasePart` a `Velocity`, and `CFrame`/`Vector3` a `:Lerp`. The ESP/Aimbot/FOV-Line paths touch all of these, and a missing one aborts the frame inside a `pcall` or throws at the render call site.

- **Every toggle carries a visible keybind chip.** `AddToggle` (via the shared `AddToggleElement` helper) appends a `Keybind` link whose `_Input` calls `AutoKeybind.Open()`, so the bind menu is reachable by a plain left click instead of the hidden right-click. `AutoKeybind.__Sync` (a no-op hook `_KeybindHandler` exposes and calls on key/mode/config changes) mirrors the bound key into the chip and stores it as `AutoKeybind.__ChipText`. `AutoKeybind.Open`/`Close` fire the same `KB_Signal` the right-click path uses.
- **`AddToggle` is a thin wrapper over `local function AddToggleElement(...)`.** The full toggle construction lives in `AddToggleElement` so other call sites can reuse it; the `Args:AddToggle` method just forwards `Config`/`Parent`/`Signal`/`Zindex`/`EnabledLine`/`DisableStackKeybind` and returns the API table. Toggles also expose `Args.Root` (the row frame) for tests and callers.

- **Runtime harness lives in `tests/`.** `tests/roblox_mock.lua` (services, players, Drawing, vector math, `RunService` connection capture, `hookmetamethod`/`getnamecallmethod` stubs, in-memory filesystem + JSON) plus `tests/harness.py`, which inlines mock + `inject.lua` + `Script/A` + an optional driver into one sandbox and writes `/tmp/setup.lua` (`SETUP_OUT` overrides the directory). Run `python3 tests/harness.py tests/<driver>.lua` then `/tmp/luaubin/luau /tmp/setup.lua`. Top-level chunks run in coroutines and are driven, because `task.wait` yields. `task.spawn` records every coroutine it creates in `G.__spawned`, and the harness adopts those into its drive list — without that, a `while true do task.wait(...) end` loop never advances and its body silently never runs, so idle-path assertions pass without exercising anything. Drivers must read harness state through globals (`__FIVESYNC`, `__M`, `__DROPDOWN_LOG`, `readfile`), not `__ENV`, because the driver chunk is a separate sandbox. `__M.ESP` exposes the ESP internals (`Config`, `ESP_Render`, `InitPlayerESP`, `ESP_Cache`, `ESP_HideAll`, `GlowSegs`, …) so a driver can turn elements on and inspect the drawings; the harness appends that export block to the `Script/A` chunk, so the real file stays untouched.

  Current drivers: `tests/esp_test.lua` (39 assertions: load reaches the end, Chams/DepthMode including the legacy `"Always"` config, Box in `Full`/`Corner`/`3D`, glow layers/intensity/leftover hiding/per-mode isolation, Tracer/Skeleton/Arrow/Circle + filled circle, Info name+distance, Life bar+text, Team Color, SelfESP on/off, `MaxDistance`, master toggle, `ESP_HideAll`) and `tests/dropdown_test.lua` (every dropdown has `Default ∈ Values`, none has a `nil` `Default` while flagged, and the Chams depth dropdown only offers real `Enum.HighlightDepthMode` items).

- **`do ... end` does not buy register budget — only `function` does.** Luau allows 200 locals in scope per function, and exceeding it is a runtime error in Roblox (`Out of local registers when trying to allocate X: exceeded limit 200`), not a compile error; `luau-compile` locally accepts far more, so the whole suite can pass while the script is dead on arrival. A top-level `do` block shares the chunk's budget, so every `local` inside it competes with the ~190 the chunk already holds. Wrap such a block in `(function() ... end)()` to give it its own budget. Run `python3 tests/register_budget.py` to check: it walks the real AST from `luau-ast`, counts locals in scope per function, and fails at 200. The Keystrokes block went from 211 locals (broken) to 39 (fine) this way; `origin/main` sits at 198, which is why it still worked.

- **`tests/mutation_test.py` is the gate, not the green suite.** It injects 18 realistic bugs into `Script/A` (enum name back to `"Always"`, glow ignoring intensity, glow leaving stale layers, Chams not destroyed on disable, 3D glow writing the Full store, SelfESP ignored, `MaxDistance` ignored, each element not drawing, `ESP_HideAll` no-op, dropdown `Default` outside `Values`) and requires every one to turn the suite red. It restores `Script/A` from `tests/.A.bak` when it finishes. A new assertion only counts if a mutation that breaks that behaviour is actually detected — the first run scored 11/18 and each survivor pointed at a real hole in the tests (the SelfESP test had been swapping the players list instead of giving `LocalPlayer` a character, so it never exercised the filter).

- **Window prefs file is shared, so write fields, not whole objects.** `FiveSync:__WriteWindowPrefs(fields)` merges the given keys into `Config.Directory .. "/Window.json"`. `SetMenuKey` writes `MenuKey`, `SetMenuButtonPos` writes `MenuButtonPos`/`MenuButtonOffset`, and `SetMenuButtonHidden` writes `MenuButtonHidden`; writing a whole table would clobber the others. Read with the matching `__Read*` helper, which returns a default when the file is missing or malformed.
- **The floating menu button is built inside `FiveSync.new` and toggled by `ToggleCloseUI`.** Anything that changes its visibility must go through `ToggleCloseUI` (or be defined after it), and `WindowArgs.MenuButtonHidden` short-circuits it to a zero-width, `Visible = false` state. `SetMenuButtonHidden` is defined *after* `ToggleCloseUI` on purpose — a `local function` referenced before its declaration resolves to a `nil` global.
- **The mode selector runs before the library and blocks the main thread.** `Script/A` opens with `EV_ModeSelector` (Performance/Full) and waits on `while not SelectedMode do task.wait(0.05) end` before the `loadstring(...inject.lua...)`. The choice is authoritative: `Performance` calls `FiveSync:OptimizeMode(true, MOBILE_CONFIG)`, `Full` leaves the library alone — including on mobile, where the old `AutoOptimize` used to force the light mode without asking. `AutoOptimize` is no longer called from `Script/A`. The selector body sits inside a `do ... end` (it declares ~40 locals) with only `SelectedMode` escaping, to stay under the 200-register cap; keep it that way when adding widgets. Its sounds are its own `SoundService` instances (`EV_ModeSelector_*`), not `FiveSync:_PlaySound`, because the library does not exist yet at that point.
- **ESP effects live on each element, not in global tables.** `Config.Box/Tracer/Info/Skeleton/Arrow/Circle/FOVLine/Chams` each carry `RGB`, `Team`, `Glow` and `GlowIntensity`; `Config.Rainbow` and `Config.TeamColor` keep only the masters (`Enabled`, `Speed`, `TeamRGB`). The old `Rainbow.ApplyTo*` / `TeamColor.ApplyTo*` switches are gone — adding an element means adding the four fields and one `AddEffects(Sec, Config.X, {team=..., rgb=..., glow=..., glowInt=...})` call in its section, which reuses the old `SecRGB_*`/`SecTeam_*` flags so saved configs keep working.
- **Glow has no shader: it is the same stroke redrawn in thicker, fainter layers.** `DrawGlow` stacks `GLOW_MAX_LAYERS` copies (1 layer under intensity 2, 2 above) with `Thickness + layer*(1.5+intensity)` and `Transparency + layer*0.18`, coloured by `GlowColor` (the element colour pulled toward white). Text uses `DrawTextGlow` (four offset copies in `TextGlow`), the arrow and the health bar pass hand-built segment buffers (`data.ArrowSegs`, `data.LifeSegs`) because a `Triangle`/`Square` has no `From`/`To`. Layers are created only while the element's `Glow` is on and merely hidden when it turns off; leftover layers from a higher intensity are hidden, never removed.
- **`CollectGlowSegs` reuses one module-level buffer.** It walks the *visible* drawings of the lists passed to it, so the halo always matches exactly what was drawn (box in `Full`/`Corner` uses `data.Box`, `3D` uses `data.Box3D`). Switching box type must `HideList` the other mode's layers, or the previous halo stays on screen. Callers pass `GlowSegs` and its returned count straight into `DrawGlow`; never keep a reference to that buffer across calls.
- **Chams is a `Highlight`, not a Drawing.** `ChamsGet` parents one per player into a `EntreVielas_Chams` Folder under `gethui()`/`CoreGui` and sets `Adornee` to the character each frame; `Fill`/`Outline` toggles work by forcing `FillTransparency`/`OutlineTransparency` to 1, and `DepthMode` maps through `Enum.HighlightDepthMode[Config.Chams.DepthMode]`. Turning chams off destroys the Highlight (`ChamsDestroy`) instead of hiding it, because a disabled `Highlight` left in CoreGui is still a game object. `HideData` only sets `Enabled = false` (it runs every frame on the skip path and must not recreate objects), while `ESP_HideAll` additionally calls `ChamsDestroy` so turning ESP off leaves nothing behind.
- **`DepthMode` must be `AlwaysOnTop`, never `Always`.** `Enum.HighlightDepthMode` only has `AlwaysOnTop` and `Occluded`, so `Enum.HighlightDepthMode["Always"]` is `nil`. Assigning `nil` to `Highlight.DepthMode` throws (`Unable to assign property DepthMode. EnumItem expected, got nil`), and because Chams is the *first* element handled in `ESP_Render`, that one throw aborted the whole frame — Box, Tracer, Skeleton, Arrow, Circle, Info and Life all silently stopped drawing. That was the real cause of "ESP does nothing": not a missing drawing, but a frame-killing enum name. The render still falls back to `AlwaysOnTop` when a saved config carries the old `"Always"` string, so existing configs keep working instead of throwing.
- **Enum members must be singletons in the mock.** `Enum.UserInputType.MouseButton1` returned a brand-new table on every read, so `input.UserInputType == Enum.UserInputType.MouseButton1` was never true and every input-type branch silently took the wrong path. Roblox hands out one table per member; the mock now caches per key. Any test that compares an enum by equality depends on this.
- **Do not stub a signal with a no-op `Connect`.** `UIS.InputChanged` was replaced by `{ Connect = function() return { Disconnect = ... } end }`, which accepts the handler and drops it. The drag test looked green while never exercising the drag code. Let `instanceIndex` hand out the real `mkSignal` instead; then `__M.__fire(svc, "InputChanged", input)` reaches the handler.
- **`RenderStepped` is captured, not signalled.** `RunService` loops land in `M.connections`, which `__drain` never touches — it only resumes coroutines. Use `__M.__step("RenderStepped", dt)` to advance frames; without it there is no way to test anything time-based like an FPS counter.
- **`QB.Registry` is keyed by id, not an array.** `ipairs` over it iterates nothing and every assertion inside the loop is skipped. Use `pairs`. The same trap applies to any registry-style table in `Script/A`.
- **A permissive mock hides exactly this class of bug.** The Roblox mock used to answer *any* `Enum.Foo.Bar` with a table, and accepted `nil` in property assignment, so `Enum.HighlightDepthMode.Always` looked fine and the render "passed". The mock now lists `HighlightDepthMode` as a strict enum (unknown item → `nil`, like Roblox), rejects `nil` property writes, and gives `Highlight` the real default `DepthMode = AlwaysOnTop` — only then does the bug reproduce locally. When a mock is more forgiving than the real API, green tests mean nothing.
- **NPCs have no `CharacterAdded`.** Hitbox/Aimbot/Magnetic all reach NPCs through `NPC_Scan(force)` in `Script/A`, which caches a `workspace:GetDescendants()` sweep for 1s. Hitbox additionally runs a 1s `HitboxStartNpcPoll` while the NPC option is on, because a model that spawns later has no event to hook.

## Workflow

- Open a PR for every finished change (base `main`).
- Keep the palette/brand consistent with the black & neon-white theme.
